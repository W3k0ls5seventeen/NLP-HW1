# Homework 1 Text Classification

This submission implements all six required experiments. Task 1 contains **two** representations (Binary Bag of Words and Word Frequency); the word "three" in the handout is a typo. Both use Logistic Regression. Task 2 compares 100-dimensional GloVe, Word2Vec trained on AG News, and Word2Vec trained on the NYT training split, each averaged over valid token occurrences and classified with Logistic Regression. Task 3 fine-tunes `google-bert/bert-base-uncased` for exactly **3 epochs** with **max_length=64**.

## Files

- `HW-1/nyt.csv` and `HW-1/ag.csv`: unchanged course datasets.
- `run_experiments.py`: data split, feature construction, training, validation and evaluation.
- `prepare_assets.py`: downloads the original pretrained resources.
- `requirements.txt`: pinned main experiment dependencies.
- `requirements-lock.txt`: complete package versions recorded for this run, including the CUDA wheel suffix.
- `results/`: the shared row split, input fingerprint, parameters, validation trials, test metrics, confusion matrices and per-example predictions.
- `HW1_Report.pdf`: English experiment report.
- `build_report.py`: regenerates the PDF from measured results (requires `reportlab==4.4.9`).
- `assets/`: downloaded resources, excluded from Git.
- `checkpoints/`: locally trained models, excluded from Git; regenerated by training.

## Environment and installation

Python 3.12 is recommended. The recorded run used Windows 11 and an NVIDIA RTX 4070 Laptop GPU. A CUDA GPU is recommended for BERT. CPU execution is supported but takes substantially longer.

From this folder in PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

For the recorded GPU environment, install the CUDA 12.8 PyTorch wheel:

```powershell
.\.venv\Scripts\python.exe -m pip install torch==2.8.0+cu128 --index-url https://download.pytorch.org/whl/cu128
.\.venv\Scripts\python.exe -c "import torch; print(torch.cuda.is_available())"
```

The pip commands need Internet access. The virtual environment is local to this folder. If `py` is unavailable, replace it with the path to a Python 3.12 executable. On Linux/macOS, use `python3 -m venv .venv` and `.venv/bin/python` in place of the Windows executable.

If the full GloVe archive or system proxy causes SSL errors or timeouts, download only its original 100-dimensional member using byte ranges:


If the Hugging Face large-file CDN is unavailable, use the verified mirror fallback:

```powershell
.\.venv\Scripts\python.exe prepare_assets.py --asset bert --bert-source modelscope
```

These two fallback commands were used for the recorded run. GloVe comes from `https://nlp.stanford.edu/data/glove.6B.zip`; only `glove.6B.100d.txt` is extracted, with ZIP CRC integrity checking. BERT is pinned to Hugging Face revision `86b5e0934494bd15c9632b12f734a8a67f723594`. The ModelScope fallback checks the **entire file** against official SHA-256 `68d45e234eb4a928074dfd868cead0219ab85354cc53d20e772753c6bb9169d3` and fails if it differs. The tokenizer and configuration are obtained from the pinned Hugging Face revision. The download source, revision and SHA-256 values are recorded in `assets/sources.json`; a copy is retained at `results/sources.json`. No Hugging Face token is required. Downloaded assets and weights should not be uploaded to GitHub.

## Experimental protocol

1. Shuffle and stratify the NYT rows with seed 42 into training (9,215), validation (1,152), and test (1,152) sets. Integer rounding produces approximately 80%/10%/10%. Save original zero-based CSV row indices in `results/split.json`. Reuse these indices for every method. Refuse to reuse them if the input fingerprint changes.
2. Use lowercase Unicode word tokens (`\b\w+\b`, including one-character words and numbers) for BoW and averaged embeddings. Do not remove stopwords, stem words, introduce bigrams, normalize BoW counts, or add TF-IDF.
3. Build the complete BoW vocabulary from NYT training text only. Binary features are 0 or 1; frequency features retain raw integer occurrence counts in sparse matrices. Use the same vocabulary for both methods.
4. Use 100-dimensional GloVe 6B vectors. Train both Word2Vec models with skip-gram, window 5, minimum count 2, 5 negative samples, subsampling `1e-3`, 5 embedding epochs, seed 42, one worker and a stable CRC32 initialization hash. Train the NYT embeddings on training rows only; train the AG model on all 90,000 unlabeled AG texts.
5. Average vectors over token occurrences that have embeddings; skip out-of-vocabulary words and use an all-zero vector if none remain. Standardize each dimension using NYT training features only. GloVe loading retains needed vectors from the fixed external vocabulary; it does not learn parameters from held-out text.
6. For every Logistic Regression model, select `C` from `[0.01, 0.1, 1, 10]` using validation Macro-F1. Use L2 regularization, the `lbfgs` solver, tolerance `1e-4`, at most 2,000 iterations, and unweighted classes. Do not refit on validation rows. Stop with an error if an LR run fails to converge.
7. Fine-tune all BERT parameters for exactly 3 epochs with WordPiece tokenization, truncation and padding to 64 tokens (including special tokens), batch size 32, AdamW learning rate `2e-5`, weight decay `0.01` except bias and LayerNorm weights, 10% linear warmup and linear decay, and gradient norm clipping at 1. Use CUDA mixed precision where available. Save the checkpoint with highest validation Macro-F1 and evaluate that checkpoint on test rows after the full three-epoch training run.
8. Compute Accuracy and unweighted Macro-F1 across `business`, `politics`, and `sports`. Save the full per-class report and confusion matrix. The test labels never select hyperparameters or checkpoints.

The NYT source contains 72 repeated text rows. They are preserved to follow the supplied row-level shuffle protocol. The shared split has 14 distinct exact texts overlapping train/validation, 10 train/test and 1 validation/test. This limits generalization claims; the report discloses it. Row IDs remain disjoint. Fixed seeds do not guarantee identical floating-point results across hardware or library versions.
